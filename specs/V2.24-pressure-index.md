============================================================
3. CANONICAL SUCCESS AND MAX SAMPLES
============================================================

For SUCCESS:

The most scientifically useful state is the PRE-GENERATION state:
the conversation state at which a real generation was successfully
accepted.

Prefer the best parser-valid pre snapshot associated with the attempt.

For MAX:

Preserve BOTH when available:

A. PRE-MAX / dispatch-state vector
B. FRESH POST-MAX vector

The production pressure model should prefer the PRE-MAX vector as the
canonical threshold observation because it represents the state at
which the failed generation was dispatched.

The post-MAX vector is supporting evidence and should remain available
for research/diagnostics.

If no valid pre vector exists but a fresh post-MAX vector exists,
allow a documented fallback rather than discarding the sample.

Do not double-count pre and post snapshots as two independent MAX
events.

============================================================
5. V2.24 PRESSURE MODEL — KEEP IT SIMPLE AND AUDITABLE
============================================================

Do NOT implement opaque ML.

Implement a small deterministic empirical model whose result can be
explained in diagnostics.

Primary predictor for the first V2.24 candidate:
DISPLAY-LIKE TOKEN ESTIMATE.

Reason:
The current real MAX samples cluster much more closely in this metric
than they do in raw mapping bytes, active-branch bytes, or retained
state.

Secondary metrics should initially be used for:
- confidence
- anomaly detection
- future research
- diagnostics

Do NOT give them arbitrary heavy scoring weights merely to make a
"multi-factor" model.

Comparable samples should prefer:

1. exact model + exact effort
2. same model when exact effort data is insufficient
3. otherwise report insufficient calibration rather than silently
   treating unrelated models as equivalent

Suggested initial pressure calculation:

- determine a comparable empirical MAX anchor from canonical MAX
  samples
- use a robust low-side MAX anchor rather than the highest observed
  MAX value
- with very few samples, a transparent min/median-style rule is
  acceptable
- once more samples exist, use a documented robust statistic

For the first implementation, a simple ratio is acceptable:

    current_display_like / empirical_max_anchor

mapped to an integer 0–99 while no verified current MAX exists.

A verified active MAX is the ONLY condition that should display
PRESSURE MAX / 100-equivalent terminal state.

Do not label the ratio as "percent context used."

If current metrics exceed the empirical anchor but ChatGPT is still
successfully operating:
- do not falsely declare MAX
- clamp the visible score below terminal MAX
- record the exceedance as useful calibration evidence
- expose this in diagnostics
